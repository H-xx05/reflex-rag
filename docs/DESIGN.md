# ReflexRAG 设计决策记录

记录"为什么这么做"——面试中被追问时,每个决策都能讲出取舍与数据。

## 1. 为什么按「条文」分块,而不是固定窗口递归切割?

法律法规是强结构化文本:第X条是立法的最小语义单元,一条内往往包含完整的
条件-结论逻辑。固定窗口切割(如 512 token 递归切)会把一条拦腰截断,
检索命中后模型只能看到半个法条,引用溯源也无从谈起。

**实现**:正则识别 `第X条`/`第X章` 边界,条文为原子(永不跨条打包),
连续条文按 ~520 字目标长度合并成块,章节/条号/发布日期进元数据。
13 部法规 → 207 块,平均 363 字/块。

## 2. 为什么用 RRF 融合而不是分数归一化?

向量检索返回余弦相似度,BM25 返回 BM25 分,两者量纲完全不可比。
分数归一化(min-max/z-score)对分布敏感、需调权重;RRF 只用排名
(`score = Σ 1/(k + rank)`,k=60),天然免调参、对异常分数鲁棒。

**实测**(51 题金标):干净法条语料上纯向量已很强(recall@8 0.892),
混合检索 recall@8 提升到 0.912,但 MRR 略降(0.857→0.817)——
BM25 对"第82条"这类精确字面查询有增益,但对语义查询会引入低相关命中。
诚实的结论:语料越"干净规整",混合检索的增益越小;这个结论本身
比"混合检索一定更好"的教条更有价值。

## 3. 为什么查询分析器一次调用同时做路由+规范化+分解?

路由(四分类)、指代消解、多跳拆解都是对同一问题的理解任务,
拆成多次调用徒增延迟与 token。一次调用输出结构化 JSON,
失败时降级为 simple 单轮检索(保可用性),不阻塞主流程。

**实测**:路由准确率 75%(vs 无路由 27%),超范围拒答正确率 100%(vs 83%)。

## 4. 为什么充分性判定而不是固定多轮检索?

固定"检索 3 轮"对简单题是浪费(延迟/成本翻倍),对难题不够。
LLM 判定证据是否覆盖问题要点,缺口(missing_aspects)直接生成
下一轮查询——检索轮数由问题难度自适应决定。
轮数上限按路由差异化(simple ≤1 轮补检,multi_hop ≤2)。

**实测**:平均轮次 1.02(44 题,绝大多数一轮即充分),
p50 延迟 2.3s 反而低于朴素 RAG 的 4.2s——因为寒暄/超范围
问题走了免检索路径,且多跳题第一轮子查询并行执行。

## 5. 为什么引用校验分两级(代码 + LLM)?

- 引用编号越界([9] 但只有 8 条证据):纯代码正则即可判定,
  零成本、零误判,发现即触发重生成;
- 陈述无据(编造数字/时限):必须语义理解,LLM 裁判抽查。

**原则**:能用确定性代码解决的绝不用 LLM,LLM 只做语义判断。

## 6. 为什么评测错误样本要单独统计?

首轮评测中 full 配置因连接错误产生 15/44 错误样本,若混入均值,
延迟/token 全部失真(p95 出现 7.6 小时)。
修正后错误率单独成列,均值只在成功样本上计算。

## 7. 已知问题与下一步(诚实清单)

- **多跳证据稀释**:多子查询分摊 top-8 名额,完整系统的证据召回
  (0.636)低于单路检索(0.841)。改进方向:多跳时动态提高
  final_top_k,或给原始查询的命中加权;
- **裁判噪声**:LLM-as-judge 用的与主模型同级,小样本下打分方差大;
  可用更强裁判模型或多人次投票;
- **正确性提升温和**(2.81→3.00):部分归因于裁判偏严+生成模型
  (qwen3.7-flash)能力上限,换更强生成模型预期拉开差距。
