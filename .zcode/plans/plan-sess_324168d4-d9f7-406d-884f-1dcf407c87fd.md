修复 Embedding 批量超限(通义 DashScope batch ≤ 20)

根因: config.py 默认 embed_batch_size=32, 超出 DashScope /embeddings 单请求条数上限。

改动(3 个文件 + 验证):

1. src/reflex_rag/config.py
   - embed_batch_size 默认 32 → 10(注释说明: DashScope 上限 20/文档口径 10, 取保守值; SiliconFlow 等支持更大, 可在 .env 调高)

2. src/reflex_rag/embeddings/openai_compat.py — 自适应降批, 不再对批量限制硬编码
   - embed_documents 中封装 _embed_with_batch_fallback(texts, size): 调用失败且错误为 400/批量相关(消息含 batch/contents)时, 批量减半重试, 直到 size=1; 恢复后按降后尺寸继续, 这样换任何供应商都不会再因批量限制挂掉
   - 降批时打印一条 warning(含最终批量), 便于用户知道可在 .env 调大 embed_batch_size

3. .env.example — 通义条目补充说明(batch 上限, 模型名 text-embedding-v4)

4. tests/test_core.py 补一个单测: 用假的 embed 函数模拟「size>20 必 400」的供应商, 断言降批后全部成功且顺序不变

验证:
- 运行 python scripts/ingest.py --rebuild, 预期输出 207 块全部入库(约 21 次批量请求, 用你 .env 里已填的通义 key)
- 跑 pytest 全绿
- 提交一个 commit

完成后你就可以直接跑: python scripts/ask.py "试用期最长多久" --trace 验证全链路。
